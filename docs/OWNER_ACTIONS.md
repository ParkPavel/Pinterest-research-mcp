## 1. Сейчас: уточнить отказ и допустимость use case у Pinterest

1. **Зачем:** получить причину отказа и порядок пересмотра; уточнить допустимость передачи выбранных изображений/метаданных в ChatGPT и ограничения хранения.
2. **Где:** https://developers.pinterest.com/apps/ → приложение → статус; затем https://help.pinterest.com/en/contact/ → раздел API/developer support, если он доступен в форме.
3. **Что ввести:** текст из [PINTEREST_REVIEW.md](PINTEREST_REVIEW.md), App ID и дату отказа в приватном обращении. Сайт `https://parkpavel.github.io/Pinterest-research-mcp/`; privacy `https://parkpavel.github.io/Pinterest-research-mcp/privacy.html`. Честно указать: локальный прототип, hosted multi-user и живые тесты ещё не готовы.
4. **Проверка:** сохранить номер обращения и ответ; отдельно проверить реальный API tier в кабинете. Владелец сообщил, что пересмотр заблокирован, и выбрал новую заявку. Перед заполнением сверить [исправленный список требований](APPLICATION_CHECKLIST.md): прежнее имя приложения недопустимо; новое независимое имя ещё не выбрано. Предыдущий отказ описывать прозрачно.
5. **Не передавать:** Client Secret, access/refresh tokens, пароли, cookies, приватные коллекции. В чат достаточно сообщить статус/номер обращения и обезличенный ответ.
6. **После ответа:** устранить указанные нарушения, сузить обработку при необходимости; выполнить живой OAuth/API тест после предоставления доступа.

## 2. До hosted-интеграции: выбрать бюджет, регион и аккаунты

1. **Зачем:** backend и OAuth не работают на GitHub Pages; нужны HTTPS-сервис, авторизация и устойчивое хранилище.
2. **Где:** сравнение в [OPERATIONS.md](OPERATIONS.md); например https://dashboard.render.com/ → New / Billing; внешний OAuth-провайдер должен поддерживать MCP discovery, PKCE и распознавание клиента.
3. **Что выбрать:** отдельные staging/production, разрешённый регион обработки и предельный месячный бюджет. Render — предварительный кандидат, не заказ. Сумма web+DB+auth+backups+egress требует отдельного подтверждения; бесплатный sleeping-host не считается production.
4. **Проверка:** после согласования записать реальные HTTPS origins, цену и лимиты; никаких placeholder redirect URI.
5. **Не передавать:** платёжные данные, приватные ключи, токены облачного API. Не создавать платные ресурсы до согласования суммы.
6. **Дальше:** реализовать и проверить hosted callback, JWT→subject→Pinterest mapping, DB-транзакции и staging CI/CD.

## 3. После реализации hosted callback: внести секреты и redirect URI

1. **Зачем:** связать конкретные окружения с Pinterest и MCP OAuth без утечки секретов.
2. **Где:** Pinterest My apps → приложение → OAuth redirect URI; выбранный хост → сервис → Environment / Secrets; OAuth provider → client/API settings.
3. **Значения:** локально `http://127.0.0.1:8765/callback` только если Pinterest принимает его. Для staging/production будет точный выделенный HTTPS-host + `/auth/pinterest/callback`; сейчас домены не существуют. MCP OAuth callback копируется отдельно из OpenAI. В secret storage: `PINTEREST_APP_ID`, `PINTEREST_APP_SECRET`, ключ шифрования и параметры выбранного провайдера по будущему runbook.
4. **Проверка:** реальный consent → callback → корректный account → API запрос; затем refresh, logout и revoke. Не принимать один успешный callback за весь тест.
5. **Не публиковать:** `.env`, токены, callback-коды, encrypted token store, DB credentials. Секреты вводятся только в защищённое хранилище, не в чат/Issues.
6. **Дальше:** два независимых пользователя, Inspector HTTP, ChatGPT и отказоустойчивость.
